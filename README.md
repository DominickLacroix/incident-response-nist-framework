# Incident Response Analysis | NIST Cybersecurity Framework

## Project Overview

This project involved analyzing a simulated cybersecurity incident and applying the NIST Cybersecurity Framework (CSF) to evaluate the organization's response and recommend security improvements.

The incident involved a Denial-of-Service (DoS) attack in which a flood of ICMP packets disrupted network services for approximately two hours. The incident response team worked to contain the attack, restore critical services, and identify security improvements that could help prevent similar incidents in the future.

---

## Scenario

The organization experienced a Denial-of-Service attack that disrupted network services after receiving a flood of incoming ICMP packets.

During the incident:

- The attack lasted approximately two hours.
- Normal internal network traffic was disrupted.
- Network resources became unavailable.
- Critical network services required prioritization during recovery.

The incident response team worked to contain the malicious traffic and restore critical services.

---

## Objective

The objective of this project was to:

- Analyze a cybersecurity incident.
- Identify the primary security weakness involved.
- Apply the NIST Cybersecurity Framework to the incident.
- Recommend security controls to reduce the risk of future attacks.
- Develop response and recovery recommendations.

---

## Attack Analysis

The incident involved a flood of ICMP packets that caused a Denial-of-Service condition.

The primary security weakness identified during the analysis was an improperly configured firewall that allowed excessive ICMP traffic into the network.

This resulted in network disruption and prevented normal internal network traffic from accessing network resources.

---

## Framework Used

This project applied the NIST Cybersecurity Framework to analyze the incident.

The following functions were used:

- Identify
- Protect
- Respond
- Recover

---

## Identify

The security team should perform regular audits of:

- Network infrastructure
- Firewall configurations
- Systems
- Connected devices

Regular security assessments can help identify weaknesses before they are exploited.

In this incident, the primary vulnerability was an improperly configured firewall that allowed a flood of ICMP packets into the network.

---

## Protect

To reduce the likelihood of similar attacks, the organization should implement additional protections.

Recommended controls include:

- Configure firewall rules to limit incoming ICMP traffic.
- Implement rate limiting for ICMP packets.
- Use source IP address verification to help detect spoofed addresses.
- Regularly review and update firewall configurations.
- Continuously monitor network traffic.

These controls can help reduce the impact of malicious network traffic.

---

## Respond

During the incident, the security team should:

1. Identify and block malicious ICMP traffic.
2. Contain the attack to prevent additional disruption.
3. Take non-critical services offline if necessary.
4. Prioritize restoring critical network services.
5. Investigate the cause of the incident.
6. Review and improve firewall rules and security controls.

---

## Recover

During recovery, the organization should:

- Restore critical network services first.
- Safely return non-critical services to operation.
- Monitor the network for additional suspicious activity.
- Review the incident and document lessons learned.
- Improve security controls to prevent similar attacks.

---

## Security Recommendations

Based on the incident analysis, the following improvements were recommended:

- Regular network and firewall audits
- ICMP rate limiting
- Source IP address verification
- Improved firewall configurations
- IDS/IPS monitoring
- Continuous network monitoring
- Post-incident security reviews
